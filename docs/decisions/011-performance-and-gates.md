# ADR-011: синтетические ограничения нагрузки и единый контроль

Расширение налогового ИИ TE с 8 до 21 IG разворачивало 2 × N² проверок выбора и
вычисление N попарных рангов. У функции выбора было 8442 поля AST. Вместо ранжирования
всех групп используется один проход: подходящие предложения, убеждаемые раньше остальных,
затем большее влияние, при равенстве более ранняя позиция в IGS. После прохода исполняется
ровно одно выбранное предложение. Код содержит 849 полей; ранги больше не вычисляются.

Эквивалентность проверена на 1500 воспроизводимых состояниях, включая равенства,
нулевое влияние, отсутствующие/маргинальные группы и отсутствие предложений. Введён
бюджет операций синтетического интерпретатора для линейного выбора; это не миллисекунды
движка. Прежние rank-values оставлены как API для возможных внешних пользователей.

Граф строится по активным файлам после маскирования путей. Категории: эффекты,
триггеры, значения, on-actions, события, задания, scripted GUI, решения, законы,
поправки, технологии и взаимодействия персонажей. Положительные задержки отделены
от немедленных рёбер; неизвестная задержка считается потенциально немедленной.
Переменные и описания не становятся вызовами только из-за совпадения имени.

Параметризованные имена раскрываются консервативно по подходящим объявлениям;
слишком широкий или динамический параметр остаётся видимым ограничением анализа.
Два домена проверены по закреплённым вызывающим участкам: PARTY имеет тип партии,
а KEY у te_tax_dr_*_touch равен agrel/regrel. Стандартные условные/отложенные циклы
сохраняются в отчёте. Их наличие не объявляется доказанной бесконечной рекурсией.

Единый tools/verify_patch.py запускает тесты, файловый аудит и граф. FAIL блокирует
упаковку и обновление установки. Обязательные условия:

- Нет неоднозначных определений в проверяемых базах и конфликтующих hook effect/trigger.
- Нет повторных callback и отсутствующих буквальных целей событий/регистраций.
- Нет безусловных циклов и новых немедленных циклических рёбер.
- Нет новых неразрешённых вызовов и новых обходов/углублений циклов по сравнению с базой.
- Сгенерированные значения/триггеры не содержат проверяемых постоянных побочных эффектов.
- Ставки и обещания проходят проверки идемпотентности; очередь синхронизации исчерпывается.
- Хеши файлов совпадают между проверкой, архивом и установкой.

Второй Python-парсер TE не понимает три смешанных списка задержек/callback в игровом
00_code_on_actions.txt. Это отмечается отдельно, а не скрывается: каждый такой блок
должен поблочно совпасть с хешированным исходником игры; изменённый неподдержанный блок
вызвал бы FAIL. Структурный парсер проекта разбирает и эти блоки.

Контроль не моделирует весь движок, GUI-кэши, произвольные динамические scopes и
условную достижимость. Поэтому он не обещает конкретный FPS или отсутствие любого
зависания. Игровые замеры и исправления по ходу кампании остаются следующей проверкой.
