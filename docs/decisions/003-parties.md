# ADR-003: партийные веса, First Past the Post и свободные выборы

Статус: реализовано и статически проверено; требуется ручная игровая приёмка.
CON-003, FR-07.

BPM не содержит стандартной цепочки ограничения размера партии через scope:number.
Поэтому сохраняются все его шаги join_weight, затем добавляются два условия TE:
бонус крупнейшим партиям с поправкой на заполнение и штраф остальным. Размеры бонусов
берутся из TE, новые числовые настройки не вводятся. Оба условия действуют только при
поправке FPTP и наличии отмеченной пары крупных партий.

11 общих партий и reactionary_party BPM получают эту композицию. TE-специфические
green/populist/technocratic сохраняют свой исходный механизм. В mark/clear/query цепочку
добавлена reactionary_party. one_party_independents — контейнер оппозиции однопартийного
режима — исключён из ранжирования и связанных самопроверок TE.

Файлы scripted_effects, scripted_triggers и script_values TE заменяются по тому же
относительному пути с сохранением остальных определений. Это не предполагает поддержки
директивы REPLACE для каждой из этих баз.

Tradition of Free Elections сохраняет награду политической инерции и условия BPM;
допустимые законы объединяются с TE, добавляется Labour Suffrage 1.15. Удалён штраф
к принятию анархии, который TE намеренно исключает. Основная поправка FPTP отдельна
от Tradition: доступность Tradition для Organic Democracy не навязывает ей FPTP.

Тесты подтверждают неизменность исходных шагов BPM, однократность добавлений, полный
жизненный цикл новой отметки, отсутствие потери вспомогательных эффектов и свойства
исторической поправки. Сила двухпартийного давления при высоких исторических весах BPM
остаётся предметом ручной проверки, а не заявленным результатом симуляции.
