# ADR-013 — воспроизводимое обновление зависимостей

Принято для инструментов сопровождения 0.6.0-dev. Игровые скрипты патча не меняются.

## Проблема

Ранее PASS связывался только с файлами патча и Python/PowerShell-инструментами.
Изменение модов или игры после проверки не обесценивало PASS при упаковке.
Версия патча и поддерживаемая версия игры были распределены по исходникам.
Ручное обновление закреплённых checkout мешало сохранять воспроизводимую базу.

## Решение

- project.json — версия патча и поддерживаемая версия игры. paths.local.json —
  игнорируемые Git локальные пути; paths.example.json — пример без личных данных.
- source_state.py связывает PASS с commits, чистотой tracked-файлов исходников,
  полным составом записанных runtime-каталогов, их хешами, локализацией, генератором,
  launcher settings, доступным Steam build ID, lock/report/project JSON.
- До и после полного контроля вычисляется один и тот же отпечаток входов. Упаковка,
  обновление установленного патча и подготовка Workshop-копии требуют свежего совпадения.
- update_patch.py check локализует добавленные/удалённые/изменённые файлы и определения,
  отмечает адаптеры и полные переопределения. Переводы строк/форматирование вынесены
  отдельно. Неизвестные изменения требуют пересмотра, а не автоматического слияния.
- update_patch.py upstream читает доступные remote refs; --fetch обновляет только
  Git-кеш. update_patch.py stage создаёт отдельные полные Git-checkout, новый отчёт,
  lock и новую версию проекта в runtime/updates. Основная база и установка не меняются.
- Новая версия игры сначала блокируется до пересмотра API и явного изменения
  supported_game_version в project.json кандидата. Один номер версии не доказывает
  совместимость: после пересмотра всё равно нужен полный контроль и игровая приёмка.
- Ранее созданный ZIP не может получить другие байты под тем же именем версии.
- update-review.json связывает решения по содержательным изменениям и новым прямым
  пересечениям с конкретными lock/research. Synthetics могут пройти до этих решений,
  но упаковка, установка и Workshop-копия остаются заблокированы. Запись решения
  требует пояснения и повторного PASS; формальное обнуление списка не является приёмкой.

## Границы

Старая исследовательская база не содержала файлов map_data TE/BPM; это отражено
в baseline_scope. Отпечаток PASS дополнительно покрывает фактические map_data и
локализацию. Новый отчёт кандидата записывает map_data полностью. Графика/звук
не хешируются целиком при каждом PASS; обновление игры дополнительно определяется
по build ID/launcher settings, модов — по commits и чистоте checkout.

Check не заменяет повторное сравнение всех пересечений и итоговый граф. Если старое
тело игрового файла уже недоступно после обновления на месте, отчёт так и сообщает.
Новые циклы, ссылки, несовместимые изменения генераторов/форматов выявляются полным
контролем кандидата; автоматического исправления неизвестной механики не заявляется.
